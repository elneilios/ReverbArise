# Proposal

## Why

Issue #10 established the working modes, but its temporary dropdown and mixed terminology do not communicate the approved creative journey. Issue #16 should establish the reusable Learn / Perform / Export header before the dedicated workspaces are built, using the newly agreed shared-control standards.

## What Changes

- Replace the temporary mode dropdown with the approved prominent three-segment selector, preserving the wordmark, italic tagline, Settings access and compact workspace proportions.
- Show active/available/unavailable states, accessible reasons, current-mode subtitles and honest recording/settlement status using existing mode authority.
- Introduce reusable library-owned segmented selection and semantic Settings-action controls plus one shared header composition; obtain owner look-and-feel acceptance before wider integration.
- Use Learn, Perform and Export in mode-related visible labels, help and living public documentation. Preserve functional terms such as Source Capture, Recapture, live wet and Audition.
- Separate display names from the existing saved Capture/Live/Finalise identifiers; preserve all capture, playback, preview, eligibility and persistence semantics.
- Use automation as primary evidence, native component feedback as work progresses and one brief final FL Studio smoke test; record their distinct coverage and preserve the merged knob-wheel fix.

No dedicated Learn/Export workspace, full-timeline audition, waveform-toolbar redesign, Character DSP, whole-plugin control migration or state/asset identity migration is included. Those remain their existing issues. Export naming does not imply that issue #6's WAV-delivery UI already exists.

## Capabilities

### New Capabilities

None. Reuse the existing workspace and workflow boundaries.

### Modified Capabilities

- `swell-workspace`: reusable shared header, segmented navigation, accessible states, responsive layout and incremental library-component approval.
- `workflow-modes`: user-facing names independent of durable identifiers, without changing transition or audio rules.

## Impact

Primary issue: #16; depends on merged #10, precedes #11. Affects `Source/UI/Controls/`, a shared header/presentation adapter, `PluginEditor` layout/refresh, mode-related visible status text, focused UI/state fixtures, and living product/design/technical guidance. No new dependency or host parameter is required. Historical plans and validation records remain unchanged. The committed #11 proposal stays on its separate branch and is reconciled with this header when resumed.
