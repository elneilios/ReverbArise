# Design

## Context

The Rack validation measured sample-aligned Host-FX MIDI and audio with a custom clock VST3 driving an exact 49,153-sample phrase. It exercised the lead-in, repeated wet, Stop and recovery. The Learn spike also captured a sequenced synth fixture. Stuart's Clock module, its musical reset and bar outputs, and the behavior of a running patch across periods and start/stop cycles remain unverified. A phrase marker establishes phase and period. Musical bar boundaries also need a verified clock and meter relationship.

## Decisions

1. **Prove musical timing in the intended hosts first.** Identify Stuart's Clock module, version and wiring. Run a small Rack patch with that module, or his patch if available, with the same clock and reset driving the audible sequence and the references routed via Host-FX. Trace the gate, audio downbeat, bar/phrase markers and VST3 events together. Measure phase and interval variation at the intended tempo and at a tempo with fractional samples per beat. Exercise start/reset, late end request, missed pulses and loss of clock. Use host transport and meter as the DAW bar authority where verified. Record the agreed Rack clock and meter mapping and its supported conditions before choosing production scheduling rules. The existing exact-period scheduler remains the policy for the proven fixture. Any tolerance or support for variable sample intervals requires separate evidence.

2. **Make the Learn capture choice explicit.** Song uses the existing playhead capture. In Loop, Arm displays the trigger it is waiting for. Fixed length starts on the configured musical Start and finishes at the selected bars-and-beats offset. Follow capture gate starts on its rising edge and treats the falling edge or configured Capture Stop as an end request. Keep recording through the first verified bar boundary at or after that request. A request exactly on the boundary ends there. Use a half-open source interval so the next bar's first sample stays outside the take. Start must identify a valid phrase origin. A DAW Start route can arm the phrase from a verified position. Host transport Stop is usable as an end request only if processing and bar timing continue through the boundary. Otherwise use a separate end request while transport is running. If reference or audio is lost before the boundary, cancel the pending take on detection and keep the last accepted take. A stopped callback stream can only be evaluated when the host next provides an observable signal or processing resumes.

3. **Make the accepted take the source for Perform and Export.** Capture an immutable identity, native rate, verified readable range and timing context. Preserve the Song reader and existing host mapping checks. Loop uses phrase-local source bounds and exposes musical labels and snapping only where the mapping is verified. Only successful acceptance changes the active take. Keep edits, prepared renders and asynchronous results pinned to their source and revision. Restore durable state silently and wait for a fresh reference and Cue for live playback.

4. **Share the creative workflow.** Adapt the existing Swells list, timeline, Overview, inspector, Settings and Audition at their source and timing boundaries. Preserve identity, selection, multiple swells, independent source and target, placement, envelopes, IR, level, activity, Freeze and reset. Run the existing automatic marker flow when selected in Learn, with verified Loop coverage and phrase-relative positions. Use production shared controls and the approved mockups. Review Song and Loop side by side at 900×600 and at 100% and 125% scale.

5. **Share preparation and use two playback authorities.** Song follows validated host position. Loop Cue schedules the earliest verified phrase boundary that leaves room for the full negative lead-in. Sum the eligible swell set off the callback. The launch plays scheduled contributions only. Later cycles reuse negative wet at the loop end and sum overlapping tails once. Admit complete prepared edits at an eligible boundary with bounded memory and transition behavior. In Rack, prove Host-FX routing from the real reference. In FL Studio, verify proposed Piano Roll notes D5 for Cue and C5 for Stop, documenting the actual MIDI numbers/channel and routing. Perform Stop cancels queued wet or promptly fades sounding wet. It takes precedence over simultaneous Cue. Sync loss returns to Standby and requires fresh Cue after lock. Dry passes through.

6. **Reuse the Export surface for Loop.** Prepare an immutable export from the accepted take and current mix. Round the WAV start back to the nearest selected grid boundary that covers the entire negative lead-in. With 2.4 bars of lead-in and a four-bar grid, the WAV begins four bars before Bar 1. Show the offset and where to drop the clip relative to the desired Playlist downbeat. A repeat count includes one initial lead-in and continuous cycle boundaries. Negative wet and overlapping tails are summed as in Perform at internal wraps, and the final scheduled wet tail is preserved. Reuse waveform, preview, mix, Save and drag behavior with bounded preparation and atomic file publication. Keep Song export unchanged.

## Risks / Trade-offs

- A cable disconnect can look like an intentional gate fall in Host-FX. Document the distinction and check whether the independently observed musical reference remains valid. Use explicit Cancel before disconnecting or suspending the host.
- A single accepted phrase can be exact without supplying usable bars or subdivisions. Withhold unsupported capture and grid options and show the missing prerequisite. Keep accepted data and keep the Song path available.
- Multiple swells, tails and export repeats increase memory and disk use. Preflight budgets off the audio thread and make incomplete or over-budget work visible.
- Persisted take, swell and asset identities must survive editor reopen, project reload and failed recapture. Keep the callback free of disk I/O, blocking and unbounded allocation or processing.

## Migration Plan

Reuse the prototype's verified reader and cue scheduler where supported. Keep its dated validation. Remove the separate prototype editor after the shared path passes and import matching prototype edits as a single swell with their available source, placement, envelope and IR settings. Preserve existing Song project identities, asset paths, cache compatibility and host identifiers. Verify with disposable copies of earlier FL Studio projects before release.
