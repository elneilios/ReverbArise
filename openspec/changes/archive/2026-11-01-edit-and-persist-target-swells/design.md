# Design

## Archive reconciliation (2026-11-01)

M3's implementation and 42 acceptance tasks are complete. The successor `automatic-lean-swell-workspace` was synced and archived first. Its accepted automatic processing, contextual/overlapping audition, neutral absent-trim default, wet placement and transition support remain authoritative. M3's delta is reconciled to preserve those contracts while adding its editing, regeneration and persistence requirements and removing the obsolete M2 session-local restriction. Historical M3 defaults and architecture below describe that milestone's original implementation, not a request to restore them. The transport change remains separate and requires its own final host acceptance.

## Context

See proposal.md for motivation. The inspected implementation has a single `PreviewEngine::current`, IR and dependency context, one `AuditionVoice`, and session-local bar fields. `PluginProcessor` saves XML state v2 with capture UUIDs/immutable manifest references and tone controls; restoration accepts v1/v2 and explicitly resets the preview. `CaptureWorker` publishes sparse committed snapshots, while the processor queues dry input before adding tone/audition. `SourceRangeReader` verifies complete coverage and uses revision-based dependency intersections; revision-only identity cannot distinguish identical recapture. Capture chunks/manifests already have immutable paths/checksums and failure-recovery tests.

The editor currently paints one global source/wet overview; `SongBarRuler` supplies fixed-tempo absolute bar ticks but no detail navigation or marker interaction. Tests cover the numerical convolution oracle, assets, supersession, callback allocation/deallocation, and offscreen controls. CMake registers 11 CTest executables. No marker model, onset analyzer, envelope renderer, managed IR/render store, or multi-swell persistence exists yet.

## Goals / Non-Goals

**Goals:** Introduce a stable editable session independent of any one resident buffer; share immutable committed dependencies; retain exact M2 convolution math; bound active memory; make save/reopen useful on the same PC/profile. Express separate render, shape, asset and request identities so UI edits cannot accidentally re-convolve or publish stale results.

**Non-Goals:** No Song-position wet scheduler, overlapping-swell mix, host transport requests, tempo-map remapping, export, Pack Project, broad relinking UI, or cache garbage collection. The existing tone scheduler remains diagnostic only. Basic persistence does not make `.flp` files self-contained. Undo/redo history and persisted unconfirmed suggestions are deferred; destructive definition edits require explicit UI actions and do not delete assets.

## Decisions

### 1. Stable model and explicit defaults

Add headless records under `Source/Core` for session, confirmed targets/swells, source intervals, shape, IR references, saved timing, and independent render status. Use UUIDs for identities and integer sample coordinates at capture rate; save fixed-tempo anchors for bar display. Candidate suggestions are transient analysis results over one committed revision. Persist confirmed edits and stable selection IDs, filtering selection when definitions are removed. Multiple selection controls batch regeneration; exactly one primary selection supplies detailed editing/audition.

Proposed defaults: confirmed arrivals create enabled, unmuted, un-soloed swells named in creation order; gain 0 dB and both fades zero, linear curves. A new source begins at its arrival and ends at the earliest of one quarter note later, the next known arrival, or the contiguous available coverage end; require at least one sample. Later detection never resizes existing sources. Source handles may be refined while keeping the arrival inside `[sourceStart, sourceEnd)`. Moving the arrival shifts source and audible offsets together, preserving fade lengths, and invalidates that swell. Source handles alone leave the arrival fixed.

Before a first render, audible start defaults to automatic raw start and audible exclusive end to arrival + 1 sample (bounded by the completed render). Store this initial automatic-start mode until a user edits the start; subsequent explicit crop offsets are relative to arrival. Provide Reset Shape / Full Render so the complete M2 response is available. Changed IR length can put an existing explicit crop outside new bounds: retain the intent visibly as invalid and require correction or Reset, rather than silently moving the edit.

Keep numeric source bar entry as a convenience, and add sample/beat precision fields rather than rounding detail edits back through integer bar controls. Snap is a UI policy, off for precise numeric edits. Alternatives: anonymous previews or page-relative markers would lose dependency identity; storing only bar numbers would lose sample precision.

### 2. Bounded offline onset proposals

Add an analysis worker using existing JUCE FFT facilities, no new dependency. Analyze a requested covered range in contiguous runs, streaming decoded source with overlap, not whole-song PCM. Use a Hann window near 21 ms (power-of-two FFT scaled with sample rate), quarter-window hop, summed positive spectral magnitude flux across channels, adaptive local threshold controlled by sensitivity, and minimum-separation peak suppression. Reset history at actual coverage gaps; do not manufacture continuity across missing assets. Include the first attack of a run with zero-padded analysis history; suggestions are hop-resolution musical aids, while confirmed/manual edits remain sample-accurate.

Use deterministic tie-breaking and cancellation/revision tokens. Discard obsolete analysis results; deduplicate candidates near confirmed targets without moving confirmed edits. Fixture acceptance measures onset proximity within one analysis window, not perfect note detection, and includes impulses, plucks, soft attacks, dense/noisy material, silence and gaps. Sensitivity/minimum separation are saved preferences; analysis output can be rerun. An amplitude-threshold-only detector was considered but would be more sensitive to input gain and sustained energy.

### 3. Immutable full convolution plus independent shape

Reuse M2 source reading, WAV/WavPack loading/preparation and FFT engine unchanged. Full raw result still spans `[P-(M-1), P+N)` with `N+M-1` stereo frames. Shape operates on `[A,B)` within that buffer, with no shift, stretch or modification of raw audio. For sample k, multiply raw PCM by per-swell gain and fade-in/out factors. Let `f(u)` be u for linear, `3u²-2u³` for smooth, or `(exp(4u)-1)/(exp(4)-1)` for exponential, with u clamped to [0,1]. Nonzero fade lengths use `(k-A)/fadeIn` and `(B-1-k)/fadeOut`; zero length means factor 1. Overlapping fades multiply. Clamp each fade length to `[0,B-A-1]` when the user narrows bounds. Gain range is -60 to +12 dB; reject non-finite parameters and overflow.

Prepare one selected shaped audition buffer and waveform/peak summary in the background. Shape request tokens are separate from convolution tokens; rapid drags coalesce and cannot change raw render identity. Stop an active voice on selection/shape/activity edits; a new prepared shape never starts playback. This retains the small allocation-free sequential voice and makes exact edited peak available before audition. Apply the existing -6 dBFS attenuation ceiling to the shaped peak, then the saved audition level (-60..0 dB, new-session default -12 dB). Show raw peak, shaped peak, automatic attenuation and predicted wet audition peak. Dry/tone contributions are separate. A callback envelope evaluator was considered but would complicate command ownership and peak/protection calculations.

Detail lanes show the full raw response as context with edited bounds/fades and shaped overlay; cropped material is dimmed. Scale over-full-scale visuals explicitly rather than flattening peaks. Muted/disabled/solo-excluded definitions stay editable/renderable but cannot audition; solo permits only enabled, unmuted soloed definitions when any solo exists. M3 auditions one primary selected swell, never mixes a batch or follows Song transport.

### 4. Multi-swell coordinator and content dependencies

Generalize `PreviewEngine` into a session coordinator with one serialized model owner and immutable UI snapshots. Use a single render worker to avoid concurrent FFT scratch expansion; independent analysis/asset jobs can run on background workers under the same budget. Key work by session generation, swell UUID, input generation and requested content signature; shape work adds shape generation. Delete/restore/Clear invalidate tokens before old completions can publish. Batch failures remain per swell and do not cancel independent valid jobs.

Fingerprint canonical source samples in exact interval order with rate/channels/bounds and required coverage; captured silence hashes identically to equivalent zero-valued audio. Stream through each relevant asset once and cache reusable content summaries; exact boundary fragments must exclude unrelated samples. Keep revision intersections as cheap dirtiness hints, then compare sample content after overlapping commits. During verification, expose a checking state and temporarily disable dependent audition. Identical content restores Ready with the same render identity and no reconvolution; changed content becomes stale. Do not claim to detect upstream MIDI changes without recapture.

Regenerate Selected explicitly rebuilds the selected set; Regenerate All queues missing/stale confirmed definitions, including muted/disabled ones, and leaves already-current audio intact. Both freeze a committed capture snapshot and managed IR reference per job. Auto-regenerate is off by default and only runs after successful commits; coalesce pending work by swell identity. Errors retain the last complete result as stale/inspectable, with retry. Stale audio never auditions as current in M3.

Extend the displayed 256 MiB working budget across source, prepared IR, FFT scratch, selected shape buffer, resident raw renders, decode scratch and pinned retired voice buffers. Keep inactive full renders on disk with compact overview peaks; unload unpinned resident audio through a worker LRU. Before allocating, evict eligible buffers or reject the particular request, never shorten its input. Include analysis buffers and bounded peak caches in accounting. A collection of one `PreviewEngine` per swell was rejected because each would retain IR/audio/scratch and independent threads without a global limit.

### 5. Scoped recapture with manual transport

Add an explicit recapture-arm record separate from passive Map while playing: absolute `[A,B)`, capture rate/timing, generation, dependent swell IDs, and fresh-coverage intervals. While armed, suspend passive outside-range admission and intersect incoming blocks with `[A,B)` before enqueueing dry samples, preserving exact sample offsets at both boundaries. Carry an arm/generation tag through queue/commit acknowledgements so coverage counts only after persistence succeeds. Keep this callback path bounded, allocation-free and lock-free.

Show “Move playhead to bar X and press Play”; do not manipulate FL Studio transport. Seek/loop captures may complete fresh coverage in separate passes; old coverage, dropped blocks and uncommitted data never satisfy missing fresh samples. Completion disarms capture, waits for all fresh samples to commit, compares content, then queues changed dependent swells. Cancel leaves newly committed actual capture intact but ends the arm and automatic follow-up. Save/reopen never restores an active arm. Source changes from unrelated passive mapping still use ordinary dependency checks. An arm flag without fresh committed coverage was rejected because it could falsely accept an incomplete refresh from old samples.

### 6. Managed assets and versioned project state

Keep M1 capture manifests unchanged. Extend the same project/instance root with immutable `irs/` canonical float WAVs and `renders/` full stereo float WAVs plus verified metadata; keep user external media read-only. Import and validate using M2 loaders, then publish canonical decoded float IR data, including WavPack correction-decoded content, so reopen does not depend on an original `.wv/.wvc` pair or its filename. Hash canonical rate/channels/frame count/sample data. Store original name as display metadata, not the identity. Render keys include exact source dependency, source positions, IR identity/preparation, timing and engine version.

Write temporary assets on a worker, flush/close, verify size/checksum, then atomically publish unique/content-addressed immutable files. Mark Ready only after its full render and metadata are committed. Share immutable content; never overwrite a saved asset or automatically delete assets on Clear, target deletion or LRU eviction. Saved project copies with the same IDs can share immutable assets while writing new generations without changing each other's saved references. Mutable convenience indexes are never authoritative saved-state references.

Introduce `PreverbState` v3 with a versioned swell metadata subtree, existing capture snapshot references and tone settings, not PCM. Serialize current compact edit records and only committed asset references; pending IR assignment remains explicitly unresolved until import publishes. Save uses a published immutable model snapshot, not disk writes or waiting for a render. Proposed defensive parsing limits: 8 MiB serialized state, 4096 swell definitions, checked sample/range arithmetic and bounded names/paths; reject a new edit with an explicit capacity message if these would be exceeded. Preserve prior valid state on unknown versions, unsafe relative paths, duplicate IDs, non-finite parameters, or invalid schema. Validate into a temporary model before installing.

Restore v1/v2 as capture/tone plus an empty collection and -12 dB default; M2 preview settings were never saved and cannot be recovered. Restore v3 definitions, saved level, analysis/auto-regeneration preferences and selection immediately, but neither voice, mapping, recapture arm nor pending commands. Stop existing voice and invalidate all old session tokens. Resolve capture first, then managed IRs/renders in a worker. Until host timing is known, show saved coordinates and an awaiting-timing state; require compatible verified timing before Ready/audition. Verify individual assets and allow unaffected swells to restore when one is missing.

A valid cached render is loaded on demand for selection, avoiding full-session RAM hydration. If the render is missing/corrupt/old-engine but source and IR are verified and timing compatible, rebuild it automatically in background regardless of the optional recapture auto-regeneration preference. Missing source/IR disables affected audition and explains which dependency needs restoration; assigning a replacement IR is an explicit edit requiring regeneration. Cross-PC packing, a general relink UI and comprehensive crash recovery remain M5. Storing only external IR paths or embedding render PCM in state was rejected because it would reproduce unreliable reopen or unbounded `.flp` size.

### 7. UI and validation integration

Split the monolithic editor into overview/detail timeline, target list, selected-swell inspector and render/asset status components under `Source/UI`. Share a tested sample-to-pixel transform for painting and hit testing; use a separate detail viewport, grid/snap, scrollbar/page controls and negative lead-in. Virtualize long lists and visible peak summaries; show coverage states distinctly. Keep tone/capture diagnostics accessible but separate from musical editing. Use offscreen software snapshots and interaction tests rather than requiring a desktop peer.

Retain all existing CTest targets and adapt M2 restoration expectations only where v3 supersedes them; keep separate v1/v2 fixtures. Add direct numerical envelope oracles, analysis fixtures, content-identity cases, scoped-capture boundary tests, worker race/cancellation tests, state/assets failure injection, independent saved-project copies and bounded-memory cases. Use callback allocation/deallocation guards through editing, recapture and audition retirement. Document and stop at an FL Studio guide covering musical editing, multiple independent swells, selected/all rendering, recapture, level protection, transport-independent audition and save/reopen with the original IR moved and render cache removed.

## Risks / Trade-offs

- [M3 is broader than M2] -> implement/test model, assets, DSP shape, coordination and UI in ordered slices; do not defer persistence or hide partial host acceptance behind checked tasks.
- [Onset quality varies by material] -> suggestions require confirmation, controls/manual entry remain available, and tests state tolerances rather than promising note transcription.
- [Exact unchanged-content checks cost disk work] -> dirty interval hints, streaming hashes and background verification; no per-sample file reads or callback hashing.
- [Shaped preview preparation uses extra RAM] -> one selected shape buffer, shared budget and explicit rejection; never copy every swell into RAM.
- [Data loss from premature asset cleanup] -> immutable references, retain sole copies and earlier snapshots; no automatic cache deletion in M3.
- [Host settings and unavailable timing vary] -> preserve original sample coordinates, require verified compatibility, test FL Studio separately and never silently time-stretch.

## Migration Plan

Add v3 parsing/serialization alongside existing v1/v2 support, preserve capture schema v1, and build immutable assets before exposing new UI operations. Run all headless and processor tests, then the documented host acceptance separately. Only sync delta specs after implementation/validation. Rolling back to an M2 binary cannot interpret v3 editing state; retain a pre-M3 test project and asset store for rollback, and make no destructive asset-format conversion. M3 writes new asset namespaces without removing prior captures.
