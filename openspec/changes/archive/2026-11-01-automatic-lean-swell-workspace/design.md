# Design

## Context

See proposal.md for motivation and scope. The current implementation is M3 at 39/42 tasks, with host acceptance still open. The handoff describes eventual automatic playback, but only diagnostic tone scheduling exists; SwellEngine uses a sequential AuditionVoice. This change must never label automatic preparation as transport playback.

Historical baseline: the automatic workspace initially had 39 completed implementation tasks and a passing 22-test suite. FL Studio feedback confirms automatic mapping/generation, but not final acceptance: one event produces several markers, envelope handles are detached and awkward, continuous tension is missing, and audition lacks sufficient original-source context. Decisions 9-12 have since been implemented and verified by a 23-test suite, bringing progress to 56/63 while seven host checks remain open. Further feedback reports ungrabbable zero fades, lack of whole-swell movement, abrupt listening boundaries and a need to audition overlapping swells. Decisions 13-17 below are approved planning refinements whose implementation/tests remain pending. Existing M3/context descriptions below identify reused components, not proof that these additions are delivered.

Observed reusable components:

| Area | Existing behavior | Work here |
|---|---|---|
| Capture | Absolute sparse dry capture before tone/audition, committed immutable assets, scoped recapture | Default-on policy for new instances; bounded committed-interval notifications |
| Detection | Streaming spectral-flux suggestions, gap resets, cancellation | Incremental context, stable accepted targets, provenance and reconciliation |
| Rendering | Per-swell immutable IR/render assets, exact content fingerprints, generation guards, single worker, 256 MiB budget | Default IR, automatic dependency dispatch, fair queue and waiting states |
| Editing | Sample-accurate source/arrival/shape, independent IR, no-FFT shaping | Musical presentation, automatic edit dispatch, protected manual ownership |
| Audition | Selected shaped wet, pinned sequential voice, -6 dB peak guard, extra -12 dB default | Aligned captured dry blend, sum protection, neutral default and visible trim |
| Persistence | v3 typed bounded metadata, async asset validation, old-state migration | Versioned automation/provenance/suppression and monitoring preferences |
| UI | Dense 1200x900 editor, left list, source/wet lanes, overview, raw fields, manual actions | Main layout and inspector refactor; retain diagnostic controls |

Relevant tests already include swell_session, swell_asset, swell_analysis, swell_shape, swell_engine, scoped_recapture, swell_viewport, swell_ui and processor integration. Keep existing regression coverage and adapt assertions only where this change intentionally supersedes old defaults.

## Goals / Non-Goals

**Goals:** Compose existing primitives into a bounded automatic preparation pipeline; retain precise model semantics; make monitoring and editing usable without diagnostic actions; preserve saved identities and assets.

**Non-Goals:** No Song-synchronized wet mixer, predictive first-pass playback, silent-insert scheduling guarantee, DAW transport control, new convolution algorithm, EQ/width/decay DSP, preset system, undo/redo or unsupported Peak Position control. The wireframe's bottom transport and additional features are omitted. Existing manual audition still depends on host processing calls.

## Decisions

### 1. Extend the coordinator instead of rewriting DSP

Feed capture commit intervals/revisions into SwellEngine on the worker side. The callback continues only timestamped bounded dry enqueue and prepared audition mixing. Record dirty intervals and merge adjacent work; UI snapshots consume committed state rather than starting scans. Detection and rendering remain background jobs under existing memory admission, including dry blend buffers and all scratch. Retain a single render worker; alternate bounded detection batches and render requests so continuous capture cannot starve rendering. Coalesce requests per ID, cap pending interval work, and retain a dirty summary for retry rather than silently losing work. Session limits remain 4096 swells and 8 MiB state; hitting limits is explicit and must not evict manual edits.

Do not rescan or rerender the entire song on each commit. Dirty intervals expand by detector context and configured separation, clipped to contiguous captured runs; current detector uses a power-of-two window at least 21 ms and a quarter-window hop. Incomplete trailing analysis context is provisional and retried on the next commit or finalized on stop using actual received samples. Gaps reset history and never supply invented zeros. Fingerprints distinguish changed samples from storage-only revision changes. Immutable job snapshots include capture scope, source fingerprint, interval, IR content, render version, channels/rate, timing and generation.

Alternative considered: a UI timer pressing the existing Analyze/Generate actions. Rejected because it creates repeated whole-range work and cannot provide stable automatic ownership or fair bounded scheduling.

### 2. Persist target ownership and reconcile deterministically

Add target provenance (automatic, manual-created, manual-edited), detector anchor, and suppression metadata to the canonical session. Suggestions remain transient. Automatic acceptance creates the swell identity once. Match candidates to existing detector anchors one-to-one, nearest distance then earliest sample then stable ID; tolerance is one analysis window capped at half configured minimum separation. Exact duplicates at a boundary collapse before matching. Manual-created/edited targets are protected; any explicit edit to an automatically created swell marks it protected. Use its detector anchor to suppress replacement near the original onset even if its arrival was moved.

For changed source, reconcile only the affected reanalyzed area. Matched unedited targets keep IDs; missing unedited automatic targets retire only after complete valid reanalysis. Failed/incomplete analysis cannot delete targets. Delete creates a persistent suppression anchor with the same matching tolerance; Diagnostics can explicitly reset suppression. Bound suppression records to 4096 and refuse further destructive suppression changes with an explanation if full; do not silently resurrect deleted targets. Selection changes only when its selected identity is explicitly removed.

Alternative considered: rebuilding the swell collection from every scan. Rejected because it would overwrite edits, per-swell IRs and selection.

### 3. Define full source windows before rendering

For newly accepted automatic targets, use source start at arrival and end at the earlier of one fixed-tempo quarter-note later or the next accepted arrival. Unlike M3's manual convenience default, do not clamp that end to currently captured coverage. A later discovered next arrival can shorten an unedited automatic source window and increment dependencies; manually edited source bounds remain protected. Render only after the entire defined interval is committed and verifies. This avoids a tiny early render being presented as the complete transient tail. If a stopped pass leaves the quarter-note tail incomplete, keep Waiting for source until replay captures it.

Continue honoring negative wet lead-in and exact exclusive bounds. Pre-roll outside the source interval needs no capture. Fixed-tempo/meter and sample-rate limitations remain; pause automatic work on incompatible timing without reinterpreting assets. Changed source marks affected results stale until replacement; default audition refuses a stale dependency except the explicitly labeled missing-dry cached-wet recovery below.

### 4. Bundle a reproducible default IR and import it through the asset store

Package a deterministic generated stereo hall-like IR as build resource data, with generator, seed, provenance/license and expected decoded checksum. It is a real decaying response, not a placeholder path. Import once per instance/content via existing canonical IR storage, then copy immutable identity into each new swell. Reuse normal preparation/resampling. Never bundle the user's IMP large_hall file. A default import failure blocks new renders with an actionable message while keeping capture and manual IR replacement available.

Changing the future default is a Diagnostics preference; selected-swell loading stays in the inspector and updates that swell only. Relinking missing assigned IR requires an explicit user assignment, never default substitution. Bundled data was chosen over an external Downloads path or runtime network dependency for reliable fresh insertion.

### 5. Dispatch minimum work after model edits

Enable mapping and automatic processing for fresh sessions. Automatic processing refreshes existing dependencies and accepts detector targets only while the separate Auto markers switch is on (decision 17). Separate persisted mapping and processing toggles permit diagnostics and recovery. Import/arrival/source changes enqueue only affected work after short coalescing (150 ms for repeated interactive edits); captured commits trigger checking on worker completion. Shape/curve/gain changes use existing shaped-buffer preparation; enabled/mute/solo and selection retain existing exclusion semantics. No edit of monitoring controls enters the convolution queue. Keep manual actions as forced recovery paths using the same dependency checks.

The header summarizes actual mapping/waiting/updating/error state, not a decorative Automatic Processing badge. List rows distinguish Waiting for source, Missing IR, Queued, Rendering, Ready, Stale/updating and Failed. Preparation never starts audition. Include a clear initial/helper indication: prepared swells are heard with Audition; Song playback of swells is a later change.

### 6. Prepare independent dry and wet audition branches off-thread

Use the selected anchor's source start S, base source end E, fixed dry arrival T and positioned shaped wet interval [A,B). In Dry + Wet mode, read captured dry context over [S,D), where D=max(E,max(T,B)+P) and P is the saved post-roll duration, default two seconds. Prepare aligned branches on [min(S,A),max(D,B)). Preserve dry samples, channel order and absolute positions throughout that context. Uncaptured wet pre-roll before S needs no dry recording, but missing samples anywhere inside [S,D) disable contextual audition with an actionable coverage message. Outside-support zeros remain intentional absence, never a replacement for missing captured context.

Transition controls apply exclusively to the wet envelope: no complementary dry fade-in, ducking, rescheduling or time stretching. The existing explicit linear monitoring blend (dry=1-w, wet=w), saved trim and disclosed contribution protection remain unchanged. Sum eligible aligned wet contributions with their saved per-swell shaping/gain, then protect that aggregate wet branch to -6 dBFS without upward normalization, check the prepared sum against its existing ceiling, then apply saved trim. This monitoring gain law does not create a transition-specific gain envelope on dry audio. Decision 15 adds separately disclosed outer audition boundary ramps; these affect only the manual replay contribution, never live dry or captured PCM.

Wet Only uses the anchor wet window and ignores the saved mixed percentage. Decision 16 defines whether that window includes overlapping neighbours or only the selected swell; it does not add a dry tail in Wet Only. New settings use Wet Only, mixed value 50%, trim 0 dB. A visible trim indicator/reset in the strip prevents an old -12/-24 dB setting becoming a hidden attenuation. Full peaks and branch/sum protection details stay in Diagnostics. Live dry passthrough remains independent; no ceiling is promised for live dry plus audition plus tone.

Extend pinned voice commands to accept prepared aligned branches/gains or an equivalent prepared composite. All reads, peak scans, preparation and retirement remain off the callback. Coalesce blend preparation; ramp transitions over 5 ms, retaining absolute sequential cursor within a continuing same-selection audition. Stop on selection or incompatible dependency changes; never restart automatically. Updating blend must not rewrite raw/shaped assets or trigger convolution.

If dry data becomes unavailable but the committed wet asset, saved IR/render identity, checksum and playback rate independently verify, allow explicit last-committed Wet Only recovery. Keep Missing source/currentness warning; this is not a Ready/current result and cannot be used to regenerate or enable Dry + Wet. Do not permit corrupt wet, incompatible rate or unverified IR dependencies through this exception. This deliberately extends M3's previous blanket current-result audition gate to satisfy the handoff's missing-dry case.

Alternative considered: mixing live input as Dry + Wet or using the wet bounds alone. Rejected because live input at stopped transport is unrelated and wet-only bounds can omit the dry attack/tail.

The context tail applies to Dry + Wet only. Wet Only retains selected wet bounds and never sneaks in captured dry playback. A tail change prepares monitoring context without convolution. Missing post-roll is shown explicitly, with the needed range retained for recapture; independently verified Wet Only remains available. Preserve an explicitly longer base source interval rather than truncating it to the tail preference.

### 7. Reorganize the editor around existing model bindings

Keep JUCE/native rendering and shared sample/pixel transforms. Split editor layout into header, virtualized left list, central source/wet detail, right inspector, audition strip, lower overview and collapsible Diagnostics. Reuse existing timeline handlers and selected-ID commands. Show other visible wet summaries with selected handles emphasized; lazily load summaries under the existing waveform budget. Do not load all PCM to draw a song.

Use absolute bar.beat.fraction positions and milliseconds/seconds for durations, with precise entry converting once to integer samples; round only at the sample boundary, never whole-bar round trips. Keep an optional sample-exact input mode in Diagnostics. Numeric source fields must reflect the selected source interval rather than stale convenience bar controls. Preserve off-grid values when snap is off. Knobs with editable values apply only to supported scalar fields; full-response/reset-shape actions remain real model operations.

Plan a default approximately 1400x900 layout, retaining a documented minimum at least as usable as the current 1100x850 through bounded pane scrolling and foldout sizing. Verify 1100x850, default and 1600x1000 offscreen before finalizing size limits. No clipping/overlap is acceptable; if a different minimum is necessary, document and validate it rather than hiding controls. Wireframe style guides hierarchy and charcoal/teal contrast, not pixel-for-pixel unsupported features.

### 8. Version migration and coexistence with active M3

Add a new plugin/session metadata version with explicit fields for mapping, automation, provenance, suppression, future default, audition mode/blend/trim. Fresh sessions enable automation/mapping. v1/v2 migrate to retained capture and empty definitions, neutral trim when absent, with automatic processing available after fresh timing. v3 retains saved trim, all existing swells as protected legacy/manual, mapping off and its old auto-regeneration preference; do not unexpectedly populate an old manual project on reopen. Explain migrated manual mode and provide an enable-automatic-processing action. New-version states persist exact preferences. Restore always stops old jobs, arms and audition, awaits verified capture and fresh host timing, then resumes permitted mapping only when the host plays.

Main specs are still at M2 while implemented M3 deltas are active. This change depends on that implementation, not on premature M3 signoff. Its reverse-convolution modifications carry forward M3 shaped/saved audition behavior and intentionally supersede M3 -12 dB defaults and manual-only/off startup policy for fresh sessions. New automatic requirements govern the new source-window/provenance behavior; M3 manual editing remains available. Record these as explicit successor behavior during acceptance. Sync/archive M3 first after actual acceptance, then this change; never apply the older delta over the newer contract.

### 9. Confirm attacks rather than accepting every positive flux peak

The existing detector's positive spectral flux can trigger repeatedly on tonal motion, decay modulation and offsets. Add an attack-confidence stage using short-term energy rise relative to preceding local context, an adaptive floor and hysteresis/rearming. Minimum separation alone must not be the fix: increasing a blind dead time can hide genuine rapid notes. Calibrate the new default acceptance policy against isolated decaying plucks, sustained tones with modulation, noisy tails, soft attacks and distinct repeated notes at supported separation. Promote the existing sensitivity to one main-view knob as specified in decision 17; keep spacing and advanced recovery in Diagnostics and document measured behavior/defaults. Any retained diagnostic sensitivity display must use that same canonical value.

Analyze enough preceding/following real captured context to distinguish an attack and retain its original onset coordinate; do not move the arrival later merely because confirmation needs more samples. Keep provisional trailing events until confirmation is possible, and reset at real gaps. Whole-run and incremental results must converge. Include detector policy/version and relevant preferences in analysis-cache identity; after an upgrade invalidate obsolete analysis summaries rather than trusting old accepted peaks. Valid reanalysis can retire unedited automatic false positives, but must preserve protected manual targets, suppression and selection under the existing ownership policy. Never silently rewrite a user's saved sensitivity just to install a new default.

### 10. Edit wet endpoint and fade independently around an anchored dry arrival

Keep arrival T and source timing fixed during an endpoint gesture. Represent the wet exclusive endpoint B as an exact signed offset from T (reusing the existing audible-end coordinate where possible). Display gap=max(0,T-B) and overlap=max(0,B-T); they are derived labels, not independent offsets that can contradict each other. Dragging B before T creates a gap, and beyond T creates overlap. Existing fade-out duration F and its tension remain independently editable; wet attenuation spans [B-F,B), clamped only to the valid audible duration, and reaches zero at the exclusive endpoint. Moving B does not reset F unless the shorter audible interval makes it invalid. Never couple fade duration to overlap or create a dry gain ramp.

Within prepared raw support, endpoint/fade/tension edits are nondestructive shaping only. A requested B beyond current render support must remain visible as requested/pending and trigger preparation of genuine support rather than being clamped to the old render, padded with invented wet silence, or stretching the old buffer. Retain the base user extraction [S,E). For the existing reverse-IR convolution, whose natural result ends at its effective excitation end, use effective render input [S,max(E,B-L)), where L is the saved wet placement offset (zero for existing sessions). Retain compatible already committed support when shortening a crop; a pending unfulfilled extension must remain cancellable. With L=0 this is the original [S,max(E,B)) policy. Body translation alone changes L and positioned B together, leaving the required raw input unchanged. Show this extension explicitly in the source lane/inspector because those additional real captured samples contribute to the wet render and can include later musical material. Do not secretly change the saved base selection, other swells, target arrival or dry playback.

Use the existing exact convolution over that effective input: N+M-1 frames at S-(M-1). Fingerprint the full effective input and include its bounds in job identity/cache validation. Wait for genuine coverage, including any needed extension; stop presenting the shorter render as current while updating. A backward endpoint edit can reuse a compatible existing extended render and reshape it without immediately discarding support. Resource limits still apply; retain the user's requested endpoint and report waiting/error if it cannot be prepared. Monitoring post-roll alone never extends convolution input.

### 11. Put direct-manipulation handles on the rendered envelope

Define one shared handle geometry for painting, hit testing and tests. Put visible endpoint, fade and tension points on the actual curve with distinct glyphs, hover/active emphasis and approximately 20-pixel hit areas. Keep source-selection handles visually separate. Label the wet-end role and show its gap/overlap relative to the dry arrival line. For collisions, use labelled offset grab targets with leader lines to their real curve anchors; both endpoint and fade-duration controls remain directly available even at zero duration. Shared geometry records the true anchor and visible grab position. Gesture deltas start from the grabbed value, so a displaced target cannot introduce a jump. Zero-length segments must not show a fictitious active tension curve. Decision 13 supersedes the previous omit-zero-fade/numeric-only fallback.

Use continuous per-fade tension in [-1,1]. Warp normalized fade time with W(u,t)=expm1(6*t*u)/expm1(6*t), using W(u,0)=u, then evaluate the selected existing Linear/Smooth/Exponential preset at that warped time. This preserves legacy curves at zero tension, monotonicity and endpoint values. Place each tension handle at the actual segment midpoint curve value; vertical dragging changes tension continuously and is reflected in a precise numeric control. The wireframe's unsupported Peak Position parameter is still not introduced.

During an active gesture paint from the accepted selected-swell edit immediately, rather than waiting for the existing 10 Hz whole-editor refresh. Keep the selected ID and viewport stable, provide fine dragging and keyboard/numeric alternatives, and make envelope fine editing independent of a coarse timeline snap grid unless snapping is explicitly requested. Coalesce background shape preparation so pointer movement cannot flood work or run PCM/convolution on the UI thread. Tension/fade edits preserve raw render identity; only endpoint support extension can require additional convolution. Add realistic envelope and pointer-interaction fixtures at the supported sizes, beyond the baseline synthetic waveform screenshots.

### 12. Migrate added editing and listening preferences without losing work

Version the added per-fade tension and any effective render-input metadata separately from immutable PCM identity where possible. Missing tension defaults to zero; preserve every saved arrival, source bound, audible endpoint, fade length, preset, IR, name, activity state, provenance and trim. Existing renders remain reusable when their support/dependencies suffice. Save the listening-tail preference, defaulting to two seconds when absent; expose a typeable 0–5 second control so one or two seconds are easy choices. Restored sessions never start audition. A new contextual audition can legitimately require capture beyond the old source window; explain that requirement rather than shortening it silently.

These refinements reuse the current managed asset and worker architecture. They add wet shaping and input-support preparation, not a new reverberation algorithm, dry-transition processor or Song scheduler. The user specifically clarified that dry stays untouched, superseding the earlier complementary crossfade draft.

### 13. Separate coincident controls and add an explicit move gesture

Always expose start/end and fade-in/out duration controls. When their normal hit areas collide, fan out labelled targets with connector lines to the actual curve anchors; retain approximately 20-pixel hit targets and deterministic priority. Hide/disable only tension for a truly zero-duration segment. Dragging a zero fade must open that fade without moving the audible bound, requiring a numeric entry, or jumping by the visual callout offset. Paint/hit-test the same layout, including at small zoom levels and editor sizes.

Reserve a visible selected wet-body/move region for whole-swell translation; precise handles take precedence. Capture initial placement and pointer position once per gesture and apply a single integer-sample delta. Immediate metadata feedback, fine movement, keyboard/numeric alternatives, stable selection/viewport and no UI-thread audio work remain required. Envelope editing keeps the existing fine/snap-independent policy; this revision does not introduce a new grid subdivision or imply Song playback. Any future snapped body move must quantize only the common translation, never each point independently.

### 14. Translate wet audio and envelope together, independently of dry

Add an exact signed per-swell placement offset L, default zero when absent. Keep immutable raw convolution in its original coordinate system. If a shaped raw crop is [a,b), its positioned interval is [A,B)=[a+L,b+L). Read raw samples at output position minus L; translate waveform summaries, handles, gap/overlap readouts and audition alignment together. Moving the body changes L only, preserving sample sequence, length b-a, fade durations, presets, tensions, gain, logical crop, IR and raw asset identity. Do not move dry arrival T, base extraction [S,E), detector anchor or another swell. Mark explicit automatic-swell movement protected under the existing ownership policy.

Individual endpoint edits remain crop/support edits: convert a positioned endpoint B back to logical raw coordinate b=B-L before computing support. Required effective input ends at max(E,b), plus any compatible retained committed support. A body move cannot cause convolution merely by passing the dry arrival; a separately extended endpoint may need genuine additional captured input as before. Use checked signed arithmetic for placement, all positioned bounds and inverse transforms; reject overflow transactionally, without independently clamping endpoints or changing their relative spacing. Preserve negative wet lead-in, cancellation, memory admission and no autoplay. Add versioned metadata and migrate all prior values unchanged with L=0; reject unsupported newer state.

### 15. Separate click prevention from musical fade editing

Reproduce click-prone cases using nonzero/DC-valued boundary samples, zero/short user fades, natural audition completion, explicit Stop, restarts, buffer replacement and very short buffers. Keep raw renders, captured PCM and saved legacy envelope parameters unchanged.

On the worker, apply a disclosed 2 ms wet-edge safety ramp to each auditioned wet contribution at its actual start/end, clipped proportionally for short intervals and reaching zero at both boundary samples. This guard is independent of editable musical fades, does not move or extend bounds and does not alter dry. Apply it before aggregating wet and measuring monitoring protection. Display the guard as monitoring protection so a zero fade field is not misrepresented as zero safety processing. The canonical envelope curve and saved shaped/raw identity remain the user's edit, not a rewritten legacy fade. A one-sample contribution cannot preserve a nonzero boundary while also reaching zero; handle it deterministically without invalid arithmetic.

Add 5 ms outer audition start/end ramps and a smooth explicit Stop, retaining exact prepared interval length and absolute cursor. Scale ramps for short buffers, reach zero at the final sample, and keep level/blend replacement handoff smooth. The outer ramp affects only replayed audition contribution, including recorded dry at the listening-window edges; it is not a complementary dry transition fade and never changes live dry or stored dry. Sample-oracle comparisons of original dry must distinguish these disclosed monitoring boundaries from the unchanged interior. Unsafe-rate/dependency invalidation may still require immediate silence. All voice work remains allocation/lock/file-I/O free in the callback and pins retire on the control/worker side.

For newly created automatic and manual swells, use placement zero, wet end T+round(rate*0.020) and a 20 ms Smooth wet fade-out at neutral tension, bounded only by valid sample geometry. This places a short wet release after the fixed dry arrival. Keep the existing fade-in initialization otherwise; zero-fade handles must still work. Resolve defaults once from compatible sample rate, not as a tempo-scheduled effect. If the default endpoint requires more than the base selection, use genuine render-support extension and honest waiting. Reanalysis, regeneration and reopen must not overwrite saved/edited shapes, including explicit zero fades. An explicit reset may adopt the documented new defaults; restoration may not.

### 16. Audition overlapping swells inside one anchored window

Add saved Isolate selected, default false when absent. It is independent of Wet Only/Dry + Wet and the stored blend/tail/trim. The selected swell defines the window W: [A,B) in Wet Only, or [min(S,A),max(D,B)) in Dry + Wet with D=max(E,max(T,B)+P). Determine W once from that anchor's positioned bounds and listening settings. Include each enabled, unmuted swell permitted by the existing global solo policy whose positioned wet interval intersects W (strict half-open intersection). Isolate selected restricts membership to that ID, still respecting activity gates. Muting the anchor must not implicitly mute eligible neighbours; valid anchor bounds remain necessary. Empty wet membership is explicit; Wet Only cannot claim audible wet, while verified Dry + Wet can still provide the dry branch.

Clip neighbour contributions to W with correct absolute offsets; do not extend W to neighbours' full bounds, include their dry audio, or recursively follow overlaps into the rest of the song. Prepare the entire selected captured dry context once, not once per member. Apply per-member user shaping/gain and wet-edge safety, sum wet without individual peak normalization, guard the aggregate wet branch, then apply the existing linear branch blend, combined-sum guard and trim. Show scope, included IDs/count and protection clearly. Overlap scope never invokes Song scheduling or capture of replay output.

Build a bounded immutable monitoring job identity containing anchor/window, scope/preferences, eligible IDs, placements, assets and generations. Hydrate/shape/mix one required member at a time under the shared 256 MiB budget; do not keep the whole song's PCM resident. Ineligible/nonintersecting results do not block audition. If a required member is stale, missing, corrupt, rate-incompatible or exceeds resources, report the specific member/reason and keep overlap audition unavailable rather than silently omitting it or using an obsolete completion. Isolate selected remains a possible explicit recovery when its own dependencies verify. Existing labelled cached-wet recovery remains per verified member and cannot masquerade as current; it does not bypass missing required members. Any included member edit, activity change, membership change or relevant capture revision invalidates the prepared group; obsolete group jobs cannot publish. Reuse valid raw assets and perform no convolution solely for scope/membership/placement/monitor controls. Stop on selection change, do not autoplay after preparation, and persist scope/placement without losing prior edits.

### 17. Expose selective automatic marking without disabling the rest of the workflow

Place one prominent rotary Marker sensitivity control with a typeable 0-100% value beside an Auto markers switch in the main header or timeline toolbar, outside the selected-swell inspector and accessible with Diagnostics closed. The value maps to the existing canonical [0,1] per-instance sensitivity; low means more conservative, favouring prominent attacks over small fluctuations in busy audio. Preserve saved values and the current fresh default (0.50/50%). This is onset/event selectivity, not musical-key or chord-change recognition. Keep minimum separation independent in Diagnostics; do not achieve a low sensitivity merely by enlarging a blind dead time. Any diagnostic copy binds to the same state, not another sensitivity parameter. Show current sensitivity, effective On/Off/Analyzing state and target-count feedback without requiring Generate or Suggest.

Add a saved autoMarkersEnabled preference, default true when absent, separate from mappingEnabled and the existing automaticProcessing master. Automatic detection/target reconciliation requires both automaticProcessing and autoMarkersEnabled. Turning Auto markers off stops automatic acceptance/reconciliation, including late publication from an in-flight analysis, but leaves existing targets, selection, suppression, capture, manual Add/Delete/edits, explicit Suggest/Confirm and the existing render-refresh policy intact. With automaticProcessing already enabled, existing manual/automatic swells continue dependency-driven rendering; marking off must not disable that master or auto-refresh as a side effect. If the master is explicitly off, show the marker controls as paused by that policy rather than silently enabling it or pretending automatic marking is active. Preserve legacy master/mapping settings, so defaulting the new preference on does not turn an old manual session automatic.

Sensitivity changes update saved state immediately but coalesce analysis work (about 200 ms after the latest adjustment or on gesture completion). The UI/callback must not scan PCM. When marking is on, queue a bounded reanalysis of committed coverage with the existing sparse-run/cell policy and latest controls. When marking is off, save the value without reconciling targets; enabling later catches up from committed coverage with those settings. Unedited automatic targets may be reconciled/retired only after a complete valid latest analysis. Protected manual edits, stable matched IDs, detector anchors, deletion suppression and unrelated assets retain their existing rules. Never clear the map or reset selection as a shortcut.

Include detector policy and relevant controls in analysis-cache identity, and a marker-control generation in publication guards so off/on or rapid sensitivity changes cannot allow an obsolete job to publish. Keep dirty summaries/catch-up work bounded, cancel superseded scans, and retain honest waiting/errors rather than using incomplete evidence to delete targets. Sensitivity changes may create/remove eligible automatic targets and thereby require only their normal dependent render work; they do not force reconvolution of unchanged swells. Disabling marker acceptance alone must not alter playback or start audition.

Calibrate low/default/high settings on deterministic busy fixtures containing strong attacks mixed with small transients and tails. Low must demonstrably reduce minor accepted markers while retaining the documented prominent fixture attacks, without requiring a longer separation setting or claiming general harmonic/key-change detection. Retain isolated/modulated-decay, soft/repeated-note, whole/incremental, gap and cancellation regressions. Verify dragging, typed values, master-off status, fresh On default, saved Off, off-during-analysis publication, re-enable catch-up and saved sensitivity in both editor/model and processor integration tests. Document measured limits and keep FL Studio usability/listening acceptance open until performed.

## Risks / Trade-offs

- [Continuous capture floods work] → Merge dirty regions, bound snapshots and requests, budget scratch, alternate analysis/render batches, expose backlog and prove finite draining after stop.
- [Detector overproduces or misses musical events] → Use existing defaults and documented limitations; preserve manual add/delete/edit and diagnostic sensitivity, deterministic fixtures and explicit target limits.
- [Changed source erases user work] → Protected ownership, stable anchors, suppression and complete-analysis-only retirement; regression tests across restore and recapture.
- [Default IR is too loud or aesthetically limited] → Owned deterministic response, audibility tests, disclosed peak guards, selected IR replacement; no universal loudness claim.
- [Gain migration surprises existing sessions] → Never raise a stored trim; show it and offer reset. Update only absent defaults.
- [Automatic generation mistaken for automatic playback] → Explicit UI/guide wording and tests proving render completion never starts wet output; transport sync remains separate.
- [Host does not call an effect while stopped] → Record actual FL Studio audition behavior; do not create host transport controls or claim unsupported silent-insert playback.
- [Attack gating misses quiet or rapid events] → Independent soft/repeated-note fixtures, measured onset tolerance, adjustable settings and preserved manual additions.
- [A longer wet endpoint needs additional musical input] → Highlight effective render-source extension, fingerprint its real samples and report coverage/resource limits; never silently alter the base source selection.
- [Envelope smoothing hides latency or overrides edits] → Immediate model-bound canvas feedback, bounded worker requests, stable gesture ownership and numeric/handle oracle tests.
- [Longer audition reaches an uncaptured tail] → Explicit missing-context state and recapture guidance, with verified Wet Only still available.

Build/test against the M3 baseline and leave host tasks unchecked until performed. Record old/new state fixtures, callback allocation/feedback checks, image reviews and fresh-insert automatic capture tests. Produce a host guide that separates preparation/manual audition acceptance from deferred scheduler tests. Roll back by reopening a pre-upgrade project copy with the old build; do not destructively migrate or delete immutable assets, and reject newer unsupported state rather than guessing. Signoff and archives remain explicit later workflows.

Keep the original completed tasks as baseline evidence and append the approved feedback work as new unchecked tasks.
