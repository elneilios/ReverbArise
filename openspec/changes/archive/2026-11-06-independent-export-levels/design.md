# Design

## Context

See proposal.md for motivation and issue traceability. The initial implementation is on PR #92: independent levels, v2 identities/state, transparent summing and reviewed controls. The owner passed FL presets, alignment and save/reopen, then requested two refinements. NoticeBar calls postAnnouncement; bundled JUCE on Windows invokes SAPI speech when accessibility clients are active. ExportVoice currently streams a completed WAV through 16 fixed 4096-frame stereo pages; gain edits stop it and preparation replaces the current prepared revision. Merely removing Stop would leave it playing the old mix. SongMix already owns verified dry/wet branches, calibration, bounded decoding and summaries; extend that mechanism instead of reconvolving or retaining whole-song PCM.

## Goals / Non-Goals

**Goals:** one accepted pair and gain-law revision through state, preparation, measurement, preview and publication; bounded page processing; truthful amplitude/peak presentation and immutable assets.

**Non-Goals:** external DAW equivalence without matched assets/routing, new output trim, Perform gain changes, a generic UI redesign or migration of unrelated controls.

## Decisions

1. **Approved transparent sum.** Owner approved on 2026-11-05: `dryLevel*capturedDry + wetLevel*acceptedWet`, independently bounded to [0,1]. Preserve per-swell render calibration, Level, shape and existing per-swell edge treatment consistently in both preview and WAV. Remove only Export aggregate wet and sum ceilings; retain rejection of non-finite samples. Measure resulting peak without altering PCM. Peak above unity produces an accessible warning, not normalization or a hidden limiter. Keep boundary start/stop/seek ramps in ExportVoice monitoring only and exclude those boundary samples from parity oracles. Existing upstream render calibration is part of the comparable accepted wet layer; do not claim equality to uncalibrated source convolution. An optional output trim would add scope and is excluded.

2. **Pair-based immutable identity.** Carry independent levels through ExportState, requests, SongExportPlan, prepared metrics, detail and ExportFile. Change songExportRevision/gain-law identity so even an identical numeric-looking legacy request cannot reuse an old crossfade WAV. Serialize canonical finite bounded values with sufficient precision; reject invalid new state. One setter updates the pair atomically for presets, coalescing one intent rather than intermediate pair revisions. Retain instance/session/pass/generation/dependency guards and previous presentation distinction. Level changes reuse accepted convolution assets, never regenerate them.

3. **Silence and dependency gating.** Gate dry reads/warnings by dryLevel>0 and wet reads by wetLevel>0, independently. Retain song origin and existing complete range policy. At 0/0 show Silent, disable preview/seek/Save/drag, and do not publish a misleading ready revision or reuse prior ready actions. Nonzero levels with all-zero PCM retain honest no-audible-start behavior. Audible Fit is calculated from the weighted accepted samples, including cancellation; waveform contributions remain separately white/aqua on one disclosed display scale. Display scaling never changes PCM. A common scale can accommodate above-unity layers without falsely clipping their drawn peaks.

4. **Preset is a pair shortcut.** Starting points are Wet Layer 0/100, Subtle 100/25, Balanced 100/50, Cinematic 100/100, Wet Forward 65/100. The owner accepted their generated comparison and passed the initial FL preset check; preserve that acceptance. Show Custom for unmatched pairs; derive matched names from canonical pair values without rounding arbitrary saved values into a preset. Retain the wet-only default as 0/100. Preset selection modifies only levels, not source, render, output gain or processing. Direct fader adjustment preserves the other level. Reuse SliderControl/NumericInputControl at the existing 0.1% edit step without reducing saved precision.

5. **Scoped control composition.** Add a compact reusable accessible preset selector using existing Controls conventions, invocation/no-wheel policy and theme; IrSelector is domain-specific and must not be copied with its IR behavior. Compose it above two shared slider/value rows in the right column. Preserve left waveform/ruler, below-waveform Zoom/Fit and percentage legend, preview transport, WAV/Save/Return and header notices. Use production Inter roles and UiGeometry spacing 4/6/12/16/24; no speculative tokens. Approve the new/revised selector family and two-fader interaction in a directly launched native preview before production integration. Any necessary variant requires scoped owner approval, standards revision and tests; never regenerate UI debt inventory to hide failures.

6. **Notices do not synthesize speech.** Remove explicit postAnnouncement from shared NoticeBar for all severities/consumers, not just the Export message string. Retain visible severity, title, description/help and normal accessibility change events; assistive software remains able to read the notice. Do not disable accessibility globally or change Narrator/OS settings. This shared interaction-policy change is explicitly in the approved follow-up scope; update UI standards and validate metadata/unchanged-refresh behavior without a new visual variant. A string-specific suppression or disabling all accessibility would leave the underlying problem or remove access.

7. **Separate moving preview from WAV publication.** Pin one verified source/timing/render/shape dependency set for the active preview. Extend SongMix with a bounded layer-read interface so worker-owned pages carry captured dry and calibrated/shaped accepted wet separately. ExportVoice consumes those pages with one coherent target pair and a linear 5 ms monitoring-only gain ramp, reusing the existing 5 ms preview boundary policy. Pair edits do not replace the preview ticket, reset its cursor or require a completed WAV. The callback performs only bounded sample mixing/atomics; no allocation, locks, decoding, file access or job scheduling. Preserve the same steady-state addition/order/calibration as WAV output. A simple restart at a saved cursor would introduce a preparation gap and lose the elapsed timeline; continued old-WAV playback would not audition the new levels.

8. **Two explicit authorities.** Preview dependency/transport ownership is distinct from the generation owning WAV preparation. Gain edits atomically persist the pair and update the active preview target for the same pinned dependencies, while invalidating current Save/drag readiness and coalescing a new immutable file request. Expose the callback-accepted target pair/revision with its absolute cursor so the waveform/legend/status cannot claim a different audible target. A retained old summary is labelled previous until matching detail exists; pending peak measurement is identified as pending. The 5 ms transition is disclosed as monitoring-only, not extra processing in the WAV. Save/drag enable only for a verified file matching the latest pair/dependencies. Old files and previously accepted host evidence remain intact.

9. **Bounded transport and cancellation.** Reuse fixed page ownership and producer/consumer cancellation, enlarging/accounting pages for two stereo branches (about 1 MiB sample storage for 16 x 4096 x 4 floats), under the existing shared budget. Prioritize servicing active preview during measurement/publication; never read full-song PCM into memory. Layer pages retain a stable session/pass/dependency ticket across gain-only edits. Latest pair intent wins without losing elapsed samples; stale jobs cannot arm a stopped voice or restore an older pair. Stop, mode exit, restore, dependency/timing invalidation, 0/0 and unrecoverable stream failure revoke playback; changing levels from stopped never starts it. After 0/0, a later nonzero pair stays stopped until Play. Keep the absolute cursor/view during playing edits, not the new mix's first audible sample. Finite timeline end still stops; if newly measured audible bounds leave no remaining audio, stop without rewinding. Do not skip sparse gaps, move DAW transport or loop implicitly. Worker starvation remains an honest stop/error, not a promised seamless result despite unavailable data.

## Risks / Trade-offs

- Above-unity addition can overload downstream playback/conversion → show actual peak and warning in accepted status; preserve Float32 values and document downstream responsibility. No automatic attenuation.
- Displayed intent can differ from retained waveform during work → label previous accepted pair and pending/error separately; disable current-file actions until matching completion.
- Legacy identity reuse or reset could detach history → preserve old descriptors and files with legacy semantics, invalidate only desired/current readiness and generate a fresh identity/path.
- Preset double updates or stale gestures can publish wrong pairs → atomic pair setter and session/pass-pinned bindings, automated out-of-order completion and restore tests.
- Cancelling layers complicates audible bounds → sample-level antiphase and sparse-gap tests, separate contribution display from summed audible Fit.
- File measurement can starve preview → service fixed layer pages first and test deliberately delayed publication while the callback advances; budget both jobs and fail honestly on stream starvation.
- Pending file metadata can mislabel audible gains → maintain a callback-accepted preview target/revision separately from file readiness and test out-of-order completion and stale summaries.
- Windows accessibility-client presence is not proof of a screen reader → remove forced synthesis; retain standard accessibility information/events and record actual screen-reader coverage honestly.
