# Read-only asset inventory — issue #8, phase 1

Phase 1 supplies bounded dependency adapters, a worker-side storage inventory and a rebuildable in-memory observation catalog. The owner-approved Storage page is integrated into Settings and scans automatically when opened. It does not change the production root, DSP, host state or asset writers. [Settings integration evidence](../validation/2026-11-06-issue-8-settings-integration.md), [backend evidence](../validation/2026-11-06-issue-8-inventory.md), [approved compatibility/backup rules](asset-storage-contracts.md) and [phase-0 measurements](../validation/2026-11-06-issue-8-storage-audit.md) define its scope.

## Adapters and dependency coverage

`Storage/AssetInventory.h` exposes `readLegacySnapshot`, `visitDependencies`, `inspect`, `Catalog` and `InventoryService`. All are control/worker APIs, never audio-callback APIs. Readers accept explicit processor XML and accepted manifest JSON, without restoring/adopting state, manufacturing silence, generating audio or replaying historical capture contexts.

The independent supported domains are processor envelope 1–8, creative state 1–12, capture schema 1/2, Export v2/unversioned legacy and managed engine 1. Sound preset metadata retains the same managed IR dependencies. Unknown dependency versions, unsafe/conflicting aliases, mismatched source identities/revisions and oversized input fail without replacing the caller's previously accepted observation. The legacy inventory deliberately treats a discovered `store.json` as incomplete scope; the separate [phase-2 portable backend](portable-asset-backups.md) now verifies its own version-1 stores. Inventory alone never certifies a pack. Schema-1 historical context stays unknown. v3 envelope ownership migration follows the processor's existing behavior; newer generation fingerprints and Auto-generate on Stop remain metadata, not execution requests.

Coverage includes source chunk paths/checksums and capture record, silence/gaps/context ownership, every historical context IR, empty IR references, default IR, retained imported-library entries, each swell's assigned IR/full retained render/calibration and all saved export-history WAVs. Frozen, disabled and stale retained references are preserved. Managed descriptors are compared with saved metadata. Source and export checksums and exact bytes are verified against inspected files; no missing file is substituted or regenerated. Coherent pack-state pinning is provided by the separate phase-2 backend; an observed inventory is not a complete-pack certificate.

## Selected roots, counts and identity

Requests select explicit local legacy instance roots (`<projectId>/<instanceId>`). There is no automatic global/user-profile traversal. The Settings provider supplies this instance's managed root and accepted capture/creative references. Identity/revision checks reject a changing observation as incomplete. Session epoch or root identity changes clear the previous report and rebind the page; ordinary edits do not start continuous scanning. Native tests inject disposable roots. Missing/offline/inaccessible roots, metadata limits, changed files/directories, unsupported formats and cancelled scans are reported as incomplete, never empty authoritative storage.

Windows handles open for read/attributes only, without delete sharing, pin inspected directories/files while in use. Root ancestors and entries reject reparse points; resolved file handles must remain under the pinned selected root. Enumeration does not follow links. File size/last-write stability is checked around hashing and directory changes invalidate a complete observation. Unicode is handled through wide Windows APIs. UNC roots and extended/long-path success are not promised; the phase-0 long-path failure remains a future path-policy gate.

File-path logical counts and unique physical counts differ deliberately. Windows volume/file IDs prevent overlapping roots and hardlink aliases from inflating physical bytes/allocation; `FileStandardInfo` supplies allocation. Categories separate captured audio, IRs/descriptors, wet renders/descriptors, capture history, protected exports, unknown temporaries and other files. Per-file metadata and `observedBy` labels identify known source revisions/saved observations; unassigned/history/unknown bytes remain protected, not reclaimable.

Exact-file SHA-256 groups are distinct from streaming decoded float32 equivalence (rate/channels/frames plus finite normalized samples). Signed-zero-distinct WAVs can be decoded-equivalent and byte-distinct. Reported duplication grants no reuse, deletion or replacement authority. Unsupported audio and files over the decode allowance explicitly skip decoded comparison. This phase never resamples or rewrites audio.

## Bounds, lifetime and uncertainty

Limits per request: 128 roots/observations, 4096 explicit active/recovery pins, 20,000 directory entries, depth 12, 16 GiB hash-byte default, 30-second cooperative processing budget, 8 MiB per manifest/creative input, 64 MiB retained scan metadata and 32 MiB maximum decoded-file input. Reference accounting caps observed edges; exceeding a limit remains uncertain/protected. Small bounded audio pages are hashed off callback. Processing limits and cancellation are checked between reads/entries; synchronous Windows storage calls can still wait for the OS. No hard I/O deadline or callback work is claimed.

The service uses request epochs to reject stale publication after cancellation/rebinding. Hiding or stopping a scan retains the last report for that instance. Reopening shows its timestamp while one fresh scan runs. Rebinding to another session epoch/root clears the report so it cannot appear under a different scope. The worker starts lazily on the first request and parks without polling while idle; page visibility schedules one request. Polling, hover, painting and audio callbacks never reschedule a scan. Destroying the page waits for its worker to settle; no maintenance lock touches audio processing.

The catalog is reconstructed in memory from supplied accepted/prior observations, immutable capture manifests, managed aliases and explicit job/reader/recovery pins. No catalog/index file is written. A missing/corrupt prior index simply lacks authority; rebuilding preserves the blanket legacy/unknown-external-reference protection. Observed manifest publication does not prove the host saved an FLP. Unobserved FLPs, external Playlist copies and cross-process jobs/readers remain explicitly unknown. No catalog count can make any asset eligible for reclamation.

## Settings and backup responsibility

`preverb_storage_inventory_preview --review` opens the isolated component composition using existing FlatSurface, text roles, EllipsisLabel, ActionButton and comfortable geometry. Opening the page automatically starts one read-only scan. Closing it cancels in-flight work and retains the last figures; reopening shows those figures while refreshing. Backup/Restore/Locate stay in a pinned bottom action bar while the information above scrolls. Text blocks use measured heights to avoid blank status gaps. There is no Inspect or manual refresh button and no continuous scanning while the page remains open. Stop scan is shown only while work is active; stopping does not restart the scan until the page is reopened. Full paths and coverage details remain accessible when values ellipsize. Phase 1 introduced no new styling token, control variant, file chooser, Pack, Relink or cleanup command. The subsequently approved [phase-2 composition](portable-asset-backups.md) wraps this inventory with working Backup/Restore/Locate controls; the inventory itself remains read-only. The component/provider binding tests cover automatic open/reopen scanning, hidden-page inactivity, stop-without-retry, worker results and scope changes. The owner approved the automatic page-open flow on 2026-11-06. preverb_storage_settings_test --review opens the actual Settings composition; its automated bindings cover tab positions, current references, reopen, session switching and unchanged saved state/render counts/file hashes. Existing About and Appearance positions are preserved.

Keep the FLP and its complete managed instance tree, including old source manifests/chunks, IRs, wet results and exports. The plugin's 256 MiB PCM working limit is not a disk-history limit. Never remove older or duplicate files because the inventory cannot prove that an older/offline FLP no longer needs them. Exact-byte packing is now supplied by the phase-2 backend. Migration, live association, writer branches, compression and any scratch administration retain their later review gates.
