# Loop Mode production handoff

**Scope.** [Issue #116](https://github.com/elneilios/ReverbArise/issues/116) adds a phrase-based Learn → Perform → Export workflow for VCV and DAWs. The existing Song workflow remains the default and keeps its host playhead timing, editor, export, project identities and assets. The feature should feel like the same plugin with a different source and timing reference.

**Start here.** Read the [four owner mockups](https://github.com/elneilios/ReverbArise/issues/116#issuecomment-6707861945), the issue’s workflow and acceptance criteria, [AGENTS.md](../../AGENTS.md), the [production UI style guide](../design/ReverbArise_UI_Layout_and_Style_Guide.md), and [UI development standards](ui-development-standards.md). Use the mockups for placement and hierarchy and the production library for actual geometry, typography, interactions and states. The early Perform image with its own Enable Loop switch is superseded. Reuse the [OpenSpec proposal, design, specs and stages](../../openspec/changes/integrate-loop-into-perform/). Some task ticks describe local spike evidence and should be reverified against the production implementation.

**Code checkpoint.** [codex/116-loop-mode-spike](https://github.com/elneilios/ReverbArise/tree/codex/116-loop-mode-spike) preserves the local experiment, including the latest Learn polish, on top of [b55c493](https://github.com/elneilios/ReverbArise/commit/b55c493) and upstream baseline [c0b8870](https://github.com/elneilios/ReverbArise/commit/c0b8870). Start production on a fresh issue branch from current origin/main. Use the spike as a reference and port individual mechanisms with their tests. ## What the user should experience

### Learn

- **Enable Loop** lives in **Learn → Source Capture** and controls the next capture. The accepted source stays visible while a replacement is armed, recording or settling. Cancellation, failure or a superseded attempt leaves that source and its edits intact. A successfully accepted new source selects the corresponding Perform and Export behavior.
- In Loop, choose **Fixed length** or **Follow capture gate**. Fixed length shows **Bars** and **Beats**. Arm waits for the configured phrase Start and records through the selected musical span while the clock continues. A later gate release has no effect in this method. For the DAW workflow, verify a timeline Start such as bar 17 with four bars ending at bar 21 while transport continues.
- Follow capture gate waits for a fresh rise. An initially high or unknown gate must first be observed low. Start defines local Bar 1 against the verified phase reference. A fall requests completion at the next verified bar. A fall on a bar completes at that bar, and the boundary sample belongs to the next span. This next-bar decision supersedes the issue body’s earlier immediate-fall wording. Keep the gate and clock roles separate. A DAW Stop that removes the timing or audio callbacks cannot finish a pending musical capture. Test the transport route and, where necessary, a dedicated capture end request while the DAW remains running.
- Show what Arm is waiting for, when the plugin is recording, when it is finishing at the next bar, and what the user can do after a failure. Give the waveform the dominant space. Identify the last accepted take and mark **Bar 1** and **Loop end** when the accepted timing supports it. Show a musical length and a human-readable duration. A closed or reopened editor should display the processor’s state and retain the verified take.
- Preserve the Song capture and generation controls. In Loop, use the same Automatic Swells option and generation lifecycle with phrase-relative markers when supported. Preserve manual and protected swells under the same rules as Song. Give the user a clear unavailable state while any Loop generation dependency is missing.

### Perform

- Extend the existing Perform editor. Keep the waveform, Swells list, Overview, timeline, inspector, multiple swells, source/target editing, envelopes, IR, gain, activity, Freeze, reset and Audition. The accepted take supplies its time domain. A Loop shows phrase-local positions including negative wet time before Bar 1. A Song retains its existing host coordinates and playback.
- Put **Cue Loop**, **Stop Loop** and status to the right of Audition, separated by a divider in the same row at 900×600. Playback stays in **Standby** with dry passing through and sync still running. Cue queues the earliest eligible phrase boundary that permits the complete lead-in. A late Cue waits another boundary. Play all negative material before Bar 1, then continue in phase. Keep queued, lead-in, playing, awaiting sync, and preparation states distinct.
- Perform Stop cancels queued wet or fades sounding wet while dry continues. Simultaneous Cue and Stop resolves to Stop. Repeat boundaries must never act as Perform Stop. Clock loss or reset clears sync, returns to a dry state with a bounded fade when needed, and requires a fresh Cue after recovery. A musician may already have heard some anticipation before Stop.
- In FL Studio, verify the proposed **D5 Cue / C5 Stop** Piano Roll notes through MIDI Out and the VST3 wrapper. Confirm the actual delivered MIDI numbers and channel, note-on handling, missing cues on mid-section starts, seeks, Playlist wraps, and offline render behavior. Cue/Stop and synchronization are separate inputs. DAW Loop can use verified host timing to establish phase while Playlist patterns bring the same prepared wet phrase in and out.

### Export

- Extend the existing Export workspace and preview, retaining **Drag WAV** and **Save WAV**. With an accepted Loop, show **Lead-in grid**, **Repeats** and **Wet level**, and label **WAV start** and **Bar 1**. Display the placement offset beside the drag action. Existing Song export retains its current behavior.
- Round file start backward to the nearest selected grid point that covers the earliest included negative wet sample. A 2.4-bar swell on a four-bar grid yields a WAV starting four bars before Bar 1, including 1.6 bars of leading silence. A target Playlist downbeat at bar 17 means dropping the file at bar 13. No negative wet means file start can be Bar 1. Require verified timing for musical grid choices.
- Use one initial lead-in. At each internal wrap, sum the next cycle’s negative wet with the prior cycle’s remaining wet. Include the final scheduled tail and avoid anticipating an unscheduled repeat. Preview, drag and save use the same prepared revision. Keep the existing mix policy, file readiness, bounds and atomic publication behavior.

Rack tests used VCV Rack Free 2.6.6, Host-FX 2.1.0 and Impromptu CLKD 2.5.0. CLKD matches the visible module in Stuart’s screenshot. His full patch, clock settings, intended tempo, physical output and FL Studio were outside the run. 280 BPM was a fixture setting near the reported 279.965 BPM, which is an observation for comparison. The older Song diagnostics showed unavailable host meter and did not establish that the other timing fields were invalid independently. Preserve the Song guards and require explicit Loop selection.

The Rack spike uses MIDI notes **14** gate/Start, **12** phrase downbeat, **19** bar, **21** beat, **22** optional reset, **16** Perform Cue, and **17** Perform Stop. Treat this as a tested wiring candidate. A disconnect can look like a release and host power or bypass can suspend callbacks. Verify behavior on the routes that ship. Document which inputs and reset assumptions a patch must provide.

## Production architecture

1. **Define accepted source ownership.** Keep the Learn preference and the accepted source separate. Publish accepted kind, stable source/revision, native rate, exclusive source extent, and optional verified musical mapping as a coherent snapshot. Song keeps its existing reader and host mapping. Loop reads its verified immutable WAV at its native rate using phrase-local positions. Audit existing project migration, cache ownership, backup and restore before making Loop durable in production. Default old projects to Song. Preserve or explicitly migrate compatible prototype takes and edits if needed. Restore verified files and retain unresolved identities when a file is missing. Reopen live wet in Standby and require fresh sync and Cue.
2. **Separate host input from capture policy.** Normalize timestamped gate, Start, beat, bar, phrase and reset events from a verified route. Process events in sample order and handle coincident edges deliberately. Use an inclusive start and exclusive end. Bound recording and staging before arming, and write/verify/publish the WAV away from the callback. Keep the prior take until publication succeeds. A clock or rate change, invalid start, missing boundary, stale generation or storage failure must fail safely. DAW timing must retain its existing consistency checks; external clock authority must be explicit.
3. **Share editing, generation and preparation.** Adapt the existing components and their bindings at the source/coordinate boundary. Start with [LearnWorkspace](../../Source/UI/LearnWorkspace.h), [PerformLayout](../../Source/UI/PerformLayout.h), [SwellEngine](../../Source/DSP/SwellEngine.h), [ConvolutionIrBinding](../../Source/UI/ConvolutionIrBinding.h) and [ExportWorkspace](../../Source/UI/ExportWorkspace.h). Keep render and selection identity rules, per-swell operations, and shared controls. Run generation and mix preparation off the audio thread. Reject obsolete jobs after edits, recapture, restore or rate changes. Prepare bounded immutable revisions and define when an edit during playback can replace the active mix.
4. **Use phrase markers for phase and share repeat composition.** At 137 BPM the measured four-bar phrase was 336,350 or 336,351 samples, and at 280 BPM it was 164,571 or 164,572. The exact fixed period policy in the prototype will reject some valid cycles. The isolated cue probe provides a candidate approach, and the production policy still needs approval for prediction, accepted interval variation, boundary correction, reset and loss of sync. Verify bounded correction on representative audio including overlapping swells. Avoid inferring meter, rate conversion or tempo stretching. Reuse pre-rendered negative wet across repeat boundaries. With an eight-second phrase, wet from −2 to 0 seconds plays before the first downbeat and sums into seconds 6–8 in a repeat. Support multiple contributions exactly once and define the resource policy for material longer than a cycle.
5. **Reuse the established exporter.** Adapt [SwellExport](../../Source/DSP/SwellExport.cpp), [SongExport](../../Source/DSP/SongExport.h) and [ExportFiles](../../Source/DSP/ExportFiles.cpp) around the accepted source and shared wrap composition. Preflight output length, repeats, sample rate and resource budget. Build the rendered snapshot and publish the file off the callback. Confirm that the displayed downbeat offset matches the rendered sample index.
6. **Preserve real-time and session contracts.** Bound callback work, avoid locks, blocking, file I/O and allocation there, and keep diagnostic history outside the processing path. Keep VST3 identity, host automation and project compatibility. Maintain instance isolation and safe lifetimes for captures, render revisions and assets.

### Spike inventory and decisions still open

- [LoopCapture](../../Source/Capture/LoopCapture.cpp) is a reference for sample-offset capture, gated/clocked transitions, verification, settlement and preservation of prior takes. Its 15-second maximum, input notes and clock tolerance are spike settings. The legacy gate-only preference is a prototype migration case.
- [LoopPlayback](../../Source/Playback/LoopPlayback.cpp), [LoopPerformance](../../Source/DSP/LoopPerformance.cpp) and [LoopPerformWorkspace](../../Source/UI/LoopPerformWorkspace.h) are the earlier single-swell, exact-period prototype. Use their focused tests and trace tooling. Production belongs in the existing editor, renderer and exporter, with shared multiple-swell semantics. The fractional CLKD policy lives in the independent [cue probe](../validation/issue-116-spike-fixtures/rack/clkd/CueTrace.cpp).
- The latest Learn UI draft is preserved for history. Use the mockups as the design target and obtain native review of both capture methods. In particular, verify density, grouped controls, method guidance, status placement, timeline labels and clear separation of next capture and last accepted take. The spike has no integrated Loop export, DAW Loop input acceptance, shared multi-swell Perform or automatic Loop markers.
- Resolve how an arbitrary captured length gets a matching recurring phrase reference, especially a one-bar take in a four-bar patch. Verify late cue, longer lead-ins, overlapping tails, tempo or rate changes, loss/relock, native DAW rendering and playback following seeks before claiming those behaviors. Start with stable repeating material and describe supported routes and limits in the guide.
