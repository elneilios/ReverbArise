# Issue #1: JUCE wet-disarm API audit — 5 November 2026

**Result:** no supported JUCE 9.0.4 API inspected reports that an upstream FL Playlist track, clip or instrument is muted, or that this mixer input will remain silent. There are useful explicit **plugin bypass** and processing-lifecycle mechanisms, but treating those as upstream source-enable information would change their meaning. This is a source/documentation result, not a claim that every FL control has been host-tested.

Explore continuation of PR #74 / [Refs #1](https://github.com/elneilios/ReverbArise/issues/1), following the [input-activity investigation](2026-11-05-issue-1-input-activity.md). Repository revision before this report: `74e672a1c80e7d7a3c9539014d5b1d9e5307a846`. Windows/PowerShell; repository CMake pins JUCE **9.0.4**, confirmed against the cached headers used by the native experiment at `C:/git/k7ma-preverb/out/build/windows-msvc/_deps/juce-src/modules`. No source, installed plugin, controller, project, capture or render changes. Connector work remains parked.

## Signal matrix

All entries below are **documentation + inspected source**, not new observed FL evidence. No API doubles or new audio fixtures were run for this audit.

| Candidate | What actually reaches a VST3 effect | Wet-disarm usefulness / limitation |
| --- | --- | --- |
| `AudioProcessor::updateTrackProperties` / `TrackProperties` | JUCE fields are only optional track name and colour. Its VST3 controller maps the corresponding channel-context attributes. | No mute, solo, source-enabled, routing-graph or upcoming-activity field. |
| `AudioPlayHead::getPosition()` / `PositionInfo` | VST3 wrapper maps playing, recording, cycle active, sample/PPQ position, tempo, meter, loop points and available timestamps. | Useful for existing transport admission. No Song/Pattern or upstream mute flag. A valid position does not imply source enabled; looping does not imply Pattern. Call only from the audio callback, not a background polling thread. |
| `getBypassParameter()` / `processBlockBypassed()` | Explicit bypass of **this effect**. If no custom parameter is provided, JUCE supplies a VST3 bypass parameter and dispatches bypassed processing when that parameter is active. | A real explicit intent signal, worth preserving/testing. Does not automatically follow another plugin, instrument, clip or Playlist mute. Current ReverbArise does not override either method; default bypass passes matching input channels through without running scheduled wet. Actual FL effect-slot switch delivery is NOT RUN here. |
| `isSuspended()` / `suspendProcessing()` | Local processor suspension state. JUCE's setter takes the callback lock; the VST3 wrapper clears the buffer when suspended. | Not an upstream mute query, and suspending would also silence dry. Do not use suspension as a wet-only gate or call its locking setter in the realtime callback. |
| `reset()` / VST3 `setProcessing(false)` | JUCE wrapper calls `reset()` when processing is disabled; default reset does nothing. This is distinct from JUCE's suspended flag. | Can be useful for clearing transient playback voices when explicitly requested, subject to the playback contract. Does not identify mute cause or imply a persistent user disarm; resets also occur for other lifecycle reasons. Current processor has no reset override. |
| `prepareToPlay()` / `releaseResources()` / VST3 `setActive` | This component's activation, preparation and resource lifecycle. | No guarantee that muting an upstream source deactivates this effect. Reconfiguration and host lifecycle changes are counterexamples to interpreting deactivation as musical intent. Absence of callbacks is not a timely semantic signal inside the callback. |
| `AudioProcessor::Bus::isEnabled()`, channel counts, layout callbacks / VST3 `activateBus` | Whether this plugin's buses/layout are enabled. JUCE may substitute silence if a disabled input bus cannot be represented by the processor's supported layouts. | Bus configuration does not enumerate source connections or source mute states. An enabled stereo bus may be receiving silence from either a valid gap or muted instruments. FL mute-to-bus behaviour is NOT RUN. |
| Input samples / `AudioBuffer::hasBeenCleared()` / VST3 `silenceFlags` | Current audio, local buffer-cleared bookkeeping, or optional zero-buffer hints. JUCE's ordinary process callback receives an AudioBuffer, not raw VST3 ProcessData or a source-disable reason. | No additional knowledge beyond the silence ambiguity. `hasBeenCleared()` is not a host track-state query. Even perfect zero detection cannot distinguish a reverse lead-in from muted source. |
| `isNonRealtime()` / `isRealtime()` / VST3 process mode | Offline/realtime processing context; VST3 wrapper sets nonrealtime for `kOffline`. | Useful for render policy, not source activity. Must not use offline as a mute reason; previous connector bounce demonstrated the probe's freshness-policy limitation. |
| `getTailLengthSeconds()` | Plugin tells host its tail duration; VST3 wrapper converts it to tail samples. | Opposite information direction: no source-state notification. Host optimisations/Smart Disable must not be used to infer source mute. |
| `PluginHostType::isFruityLoops()` | Identifies FL as host. Wrapper's FL-specific locking and state-stream workarounds address host compatibility. | No project mode/mute query. FL-specific code in JUCE is not evidence of access to the FL native plugin SDK. |
| `VST3ClientExtensions` | Optional access to host/component-handler interfaces and ability to expose additional plugin interfaces. Standard `IHostApplication` supplies name/object creation; standard channel context adds identity/index/location metadata, not mute. | A genuine extension point, but not a source-state API by itself. No documented FL VST3 interface providing the required state was established. An undocumented/private interface cannot be assumed available; another plugin format's SDK is insufficient. |
| VST3 `IPrefetchableSupport` / `kPrefetch` | Lets plugin declare whether host-managed prefetch processing is supported. Host chooses processing schedule. | Does not let the plugin request an independent future mixer render or guarantee seconds of advance input. Not a substitute for actual lookahead. |
| JUCE ARA extensions / ARA audio readers | Optional integration with an ARA host's document/audio-source model. ReverbArise does not enable/build ARA integration. | Architectural route to random-access source data in supporting hosts, not a hidden AudioProcessor feature. FL binding/support for this use is not established, nor would raw source data alone guarantee the future output of live instruments and arbitrary upstream FX. |
| `AudioProcessorGraph`, `AudioPluginInstance`, plugin-hosting APIs | Manage processors instantiated/owned by our own hosting graph. | Cannot enumerate or render FL's unrelated instruments/effect graph. Hosting a second instrument instance would not reproduce arbitrary current project state or future live input. |

No source-mute interface was found in the inspected standard headers.
- [`ARA SDK`](https://github.com/Celemony/ARA_SDK) documents its separate host/plugin integration. This audit does not infer current FL ARA support from JUCE's ability to build ARA plugins.
- [FL wrapper documentation](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/wrapper.htm) warns that Smart Disable can interfere with time-based effects and expected starts. [FL mixer documentation](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/mixer.htm) distinguishes mixer-track mute and post-effect faders from upstream Channel Rack controls. A mixer output mute is a useful host-side way to silence the resulting track, without the plugin discovering why it was muted; it has broader scope than wet-only disarm.

## Recommendation and remaining empirical question

Separate **explicit intent** from **input inactivity**. JUCE supports explicit bypass/parameters, callback-safe transient gates and transport-aware scheduling. It does not expose the missing upstream intent through the APIs inspected. Keep saved user playback enable separate from any temporary context/gate; never clear source, render readiness, revisions or persistent identities to implement a mute. Learn Pattern capture and dry pass-through remain protected.

The smallest unresolved host experiment would log this separately identified probe's reset, prepare/release, bus changes and bypass callbacks alongside audio/transport while the owner toggles (a) Playlist track, (b) Channel Rack source, (c) mixer track and (d) effect-slot enable. Include a silent enabled source as the control. If an event appears, first show it differs from normal stop/start, seeks, device resets, Smart Disable and source silence before treating it as evidence. It must arrive before unwanted audio, across realtime and offline, without depending on an open editor. One correlated lifecycle event would not establish a reliable source-enable contract. This experiment is proposed, **not run**, and no new host session is requested here.

**NOT RUN:** new FL mute/lifecycle traces, new native probe/build/install, native bypass audio tests, ARA host binding, FL private-interface discovery at runtime, or lookahead/PDC tests. Existing native connector results are not relabelled as evidence for these APIs. No production implementation or OpenSpec proposal is created. OpenSpec list commands were attempted but the local launcher reported no active Node version; no toolchain settings were changed, and the existing relevant spec was read directly.
