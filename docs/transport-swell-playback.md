# Song transport playback

Song-synchronized playback is implemented. Automated tests exercise the live mixer; acceptance of the current UI build is tracked separately in [current checks](ui-diagnostics-and-acceptance.md).

New and migrated instances store independent live settings: playback enabled, Dry + Wet routing, and 0 dB user wet level. Live level accepts -60 through 0 dB. Manual Audition trim, blend, isolation and listening tail remain separate. Session JSON and plugin state are version 7; v1-v6 input remains supported and preserves its existing edits and monitoring values.

Default Dry + Wet output is unchanged live input plus prepared wet. It does not replay captured dry. Enabled Wet Only suppresses live dry only during playing Song transport; disabling or stopping returns dry with a short routing transition. Settings > Playback controls for Live playback, routing and Live wet are independent of the manual Audition strip.

Song playback requires a coherent host observation containing absolute samples, PPQ, sample rate, tempo, meter and playing state. Only fixed mappings compatible with the prepared capture are supported. Two inferred sample-to-PPQ origins can differ by at most one sample, allowing independently rounded host observations. A larger difference, a rate/tempo/meter change, invalid fields or an overflowing origin is incompatible rather than a request to stretch/remap existing audio.

For example, at 48 kHz and 120 BPM, sample 145000 / PPQ 6 has the same origin as sample 1000 / PPQ 0. Seeking backward to sample -23000 / PPQ -1 also retains that origin. Changing the latter to sample -22998 exceeds the one-sample tolerance. Automated transport timing tests exercise these cases and the fractional 82 BPM mapping.

Prepared pages belong to individual swells. A stale, muted or edited contribution can therefore stop while valid overlapping neighbours continue. All session solo flags participate in the existing solo filter, even if the soloed item is disabled or muted. Selection and Isolate selected affect manual preview, not live playback. Source arrival remains fixed when moving wet audio or editing its gap/overlap.

The worker prepares up to 96000 forward frames and one eighth as much behind the current position: two seconds ahead plus 250 ms behind at 48 kHz. At higher rates the frame cap shortens the time window. The same bounded window is prepared around a supplied loop destination outside the main window. The plugin does not allocate intervening song silence. Assets are read and shaped on the worker in 4096-frame chunks; raw PCM need not be loaded for an entire song or render. Prepared and retired pages share the existing 256 MiB PCM allowance with render, audition and decode work. A capacity failure is displayed rather than admitting unaccounted memory.

Admission allows 64 simultaneous eligible swells. A schedule exceeding that limit reports unavailable live playback instead of silently omitting extra voices. The callback uses prepared interval segments and fixed voice storage, with no disk reading, convolution, allocation, deallocation or locks. Valid positioned blocks up to 1048576 frames are supported; larger or overflowing sample intervals are unavailable. The callback still preserves the selected dry routing and discharges old wet safely.

A warm seek reads the destination's actual samples. A seek outside prepared coverage shows a miss; the worker prepares near the new position and output joins the then-current offset. It never replays missed lead-in. Allow preparation before critical realtime playback. Host-marked offline bounce uses synchronous preparation described below. The UI reports window preparation rather than promising a completely resident song. A host which suspends processing on silent/idle inserts cannot receive sound from plugin code until callbacks resume; that behavior needs FL Studio validation.

The saved per-swell envelope and gain are followed by a 2 ms crop-edge safety ramp, shortened for very short buffers. Transport admission, replacement, stop/seek/miss, dry routing and live level changes use at most 5 ms transitions. Continuous page boundaries do not restart crop fades. These listening safeguards do not rewrite stored renders, shift source notes or change edited fade/tension values.

Wet protection uses one fixed gain per schedule revision. For each swell the worker measures its shaped, safety-ramped peak, then bounds the largest overlapping sum of those peaks. It attenuates that bound to -6 dBFS without boosting quiet material. For overlapping peaks of 2 and 3, the gain is 10^(-6/20) / 5; for the same nonoverlapping peaks it is 10^(-6/20) / 3. The gain remains unchanged when only resident windows change. It can be conservative; the UI displays its attenuation separately from Live wet. Dry + wet together can exceed full scale because live dry is not limited.

Enabled Song playback stops and inhibits manual Audition, avoiding sustained duplicate wet output. Stopping the Song never starts Audition. To use the old sequential preview while transport runs, disable Live playback explicitly. Audition trim/blend/tail do not set live gain or timing.

Recapture is compared by actual source fingerprint. Identical and unrelated commits retain verified audio; changed dependencies invalidate the affected member before its replacement is prepared. IR/shape/placement/activity edits use generations so cancelled completions cannot publish. Missing-source cached wet remains available only through the explicitly labeled manual Wet Only recovery path. A render explicitly frozen while ready is separately eligible for live playback after render verification. Clear/restore resets voices and requires fresh host timing and verified assets. Upstream edits cannot be known before recapture.

## Performance variation, Freeze render and DAW export

Regeneration sensitivity is a separate, typeable knob in the main header. It does not change Marker sensitivity or marker creation. At the default 50%, source comparisons tolerate 15% change in coarse spectral amplitude profiles; at 0% they tolerate 30%, and at 100% comparisons are sample-exact. Comparisons use stereo four-band RMS amplitudes in 50 ms windows, with an absolute quiet floor of 0.001 summed band amplitude. Small level/phase/noise differences usually retain the committed source. Larger changes commit new source and refresh affected dependencies. This is a heuristic: equal coarse profiles can conceal some changes, and timing shifts or short chunks can still refresh. Ignored input never replaces the baseline, so small changes cannot accumulate unnoticed. Explicit scoped recapture bypasses tolerance.

Freeze render in the selected-swell inspector fixes ready committed wet against automatic source changes. Frozen swells are marked in the list and protected from automatic detection reconciliation. Name, activity, shape, gain and wet placement remain editable. Unfreeze before changing source/arrival/IR or extending render support; unfreeze checks current source and regenerates as necessary. The saved frozen render works after capture clear or reopen without source/IR availability, provided its managed wet file is intact and rate/tempo/meter match. Captured Dry + Wet audition still needs genuine dry context. Timing incompatibility and missing/corrupt wet remain explicit failures. Existing sessions migrate to 50% Regeneration sensitivity and unfrozen swells.

For DAW WAV export, the host must identify offline processing (JUCE isNonRealtime, VST3 kOffline). The plugin then pauses background preparation, verifies/completes existing swell definitions and holds a fixed snapshot for the bounce. It skips recording export input and synchronously reads/shapes bounded pages before mixing. Pages are normally 16384 frames and shrink under budget pressure; host blocks are sliced into at most 512 frames. PCM shares the 256 MiB allowance. The whole song need not be resident. Eligible overlaps, fixed wet attenuation and saved routing apply; offline Wet Only starts without a dry-routing fade-in. Host Playing need not be true, but absolute sample/PPQ mapping is still required.

Offline processing can wait, allocate and read disk; ordinary realtime processing still cannot. Waiting or missing individual swells produce a prominent `Export warning: ...` naming skipped members while all available wet continues rendering. This follows the same available-contribution policy as live playback. Fatal mapping, budget or unexpected admitted-page I/O failures still report `Export incomplete: ...` persistently. The VST API does not let this effect cancel the host's export dialog, so inspect the result: a skip warning means partial wet output, while a fatal export error means the bounce could not continue correctly. Hosts that do not flag offline processing retain the realtime prefetch behavior and need host-specific investigation. First capture the song and allow automatic marker creation before exporting; export is not a first-pass source discovery mode. Full project packaging and standalone export controls remain later work.
